### 线程生命周期
1. **新建（New）**：当创建一个线程对象时，线程进入新建状态。此时线程还没有开始执行，只是被分配了内存空间并进行了一些初始化操作。例如：`Thread thread = new Thread();`。
2. **就绪（Runnable）**：调用线程的`start()`方法后，线程进入就绪状态。在这个状态下，线程已经准备好执行，但还没有获得CPU时间片，需要等待操作系统的调度。
3. **运行（Running）**：当操作系统为线程分配了CPU时间片后，线程进入运行状态，开始执行`run()`方法中的代码。
4. **阻塞（Blocked）**：在运行过程中，线程可能会因为某些原因进入阻塞状态，如等待获取锁、等待I/O操作完成、调用`Thread.sleep()`方法等。处于阻塞状态的线程不会占用CPU时间片，直到导致阻塞的原因解除，线程才会重新回到就绪状态。
5. **死亡（Dead）**：当线程的`run()`方法执行完毕或者因为异常等原因提前终止，线程进入死亡状态。此时线程的生命周期结束，不再具备执行能力。

### 线程中断方式
- **使用`interrupt()`方法**：这是一种较为常用的中断线程方式。当在一个线程中调用另一个线程的`interrupt()`方法时，会设置该线程的中断标志位。线程可以通过检查这个标志位来决定是否停止执行。例如，在循环中可以使用`while (!Thread.currentThread().isInterrupted())`来判断线程是否被中断，当标志位被设置为`true`时，循环结束，线程执行结束。
- **通过异常处理**：如果线程在阻塞状态下（如`wait()`、`sleep()`或`join()`方法）被中断，会抛出`InterruptedException`异常。可以在捕获到这个异常后进行相应的处理，如结束线程的执行。示例代码如下：
```java
try {
    Thread.sleep(1000);
} catch (InterruptedException e) {
    // 处理中断逻辑，例如设置标志位或直接结束线程
    Thread.currentThread().interrupt(); // 重新设置中断标志，以便上层方法也能感知到中断
}
```
- **使用标志位**：定义一个`volatile`类型的变量作为标志位，在线程中通过检查这个标志位来判断是否需要中断线程。当需要中断线程时，修改标志位的值，线程在运行过程中检测到标志位的变化后，执行相应的中断逻辑。示例代码如下：
```java
public class MyThread extends Thread {
    private volatile boolean stopFlag = false;

    @Override
    public void run() {
        while (!stopFlag) {
            // 线程执行的任务
        }
    }

    public void stopThread() {
        stopFlag = true;
    }
}
```

需要注意的是，中断线程时要确保线程能够安全地停止，避免出现资源未释放、数据不一致等问题。同时，不同的场景可能需要选择不同的中断方式，以满足程序的需求。
