进程与线程的区别
进程（Process）和线程（Thread）是操作系统中两个重要的概念，它们在资源分配、执行效率、通信方式等方面存在显著差异。以下是详细的对比：
--------------------------------------------------------------------------------
1. **定义**
   进程
- **定义**: 进程是操作系统进行资源分配和调度的基本单位，每个进程拥有独立的地址空间。
- **特点**:

- 每个进程有自己独立的内存空间、代码段、数据段等资源。
- 进程之间的切换开销较大，因为需要保存和恢复完整的上下文环境。
  线程
- **定义**: 线程是进程中的一个执行单元，多个线程可以共享进程的资源（如内存、文件描述符等），但各自拥有独立的栈空间。
- **特点**:

- 同一进程内的线程共享内存和其他资源，因此线程间的通信和同步相对简单。
- 线程切换开销较小，因为只需要保存和恢复少量的寄存器和栈信息。
--------------------------------------------------------------------------------
2. **资源分配**
   进程
- **独立性**: 每个进程都有独立的地址空间、打开文件列表、信号处理机制等。
- **资源占用**: 创建和销毁进程的代价较高，因为需要分配和回收较多的系统资源。
  线程
- **共享性**: 同一进程内的线程共享大部分资源，如内存、文件描述符、信号处理机制等。
- **资源占用**: 创建和销毁线程的代价较低，因为只需要分配和回收少量的资源（如栈空间）。
--------------------------------------------------------------------------------
3. **通信方式**
   进程
- **进程间通信（IPC）**: 进程之间不能直接访问对方的内存空间，必须通过 IPC 机制进行通信，常见的 IPC 方式包括：

- 管道（Pipe）
- 消息队列（Message Queue）
- 信号（Signal）
- 共享内存（Shared Memory）
- 套接字（Socket）
  线程
- **线程间通信（TIC）**: 同一进程内的线程可以直接访问共享内存，因此线程间通信相对简单，常用的 TIC 方式包括：

- 共享变量
- 锁（Lock）
- 条件变量（Condition Variable）
- 信号量（Semaphore）
--------------------------------------------------------------------------------
4. **并发性**
   进程
- **并发性低**: 由于进程切换开销大，创建和销毁进程较慢，因此并发性较低。
- **适合任务**: 适用于需要独立运行且资源隔离的任务，如不同的应用程序或服务。
  线程
- **并发性高**: 线程切换开销小，创建和销毁线程较快，因此并发性较高。
- **适合任务**: 适用于同一应用内的并发任务，如多任务处理、I/O 操作、计算密集型任务等。
--------------------------------------------------------------------------------
5. **错误处理**
   进程
- **隔离性强**: 如果一个进程崩溃，不会影响其他进程。进程之间的错误隔离较好，安全性较高。
- **恢复复杂**: 需要额外的机制来监控和重启失败的进程。
  线程
- **隔离性弱**: 如果一个线程崩溃，可能会影响整个进程，因为线程共享进程的资源。
- **恢复简单**: 可以通过捕获异常并处理来恢复单个线程，而不需要重启整个进程。
--------------------------------------------------------------------------------
6. **应用场景**
   进程
- **独立应用**: 如浏览器、文本编辑器、数据库服务器等，每个应用通常作为一个独立的进程运行。
- **资源隔离**: 当需要严格隔离资源时，使用进程可以避免相互干扰。
  线程
- **多任务处理**: 如 Web 服务器、视频播放器等，可以通过多线程实现并发处理多个请求或任务。
- **响应速度**: 对于需要快速响应的应用（如 GUI 应用），多线程可以提高用户体验。
--------------------------------------------------------------------------------

# 如何中断线程

在Java中，中断线程有以下几种方法及原理：

### 使用`interrupt`方法
- **方法介绍**：在线程对象上调用`interrupt`方法，它并不会立即中断线程，而是设置线程的中断标志位为`true`。
- **原理**：线程可以通过检查自身的中断标志位来决定是否停止执行。例如，当线程处于阻塞状态（如`wait`、`sleep`、`join`等方法导致的阻塞）时，如果被中断，会抛出`InterruptedException`异常，同时会清除中断标志位，线程可以在捕获该异常后进行相应的处理，如结束线程执行。对于非阻塞状态的线程，需要在代码中合适的位置主动检查中断标志位，如通过`Thread.currentThread().isInterrupted()`方法来判断，并根据结果决定是否终止线程。

示例代码如下：
```java
public class InterruptThreadExample {
    public static void main(String[] args) {
        Thread thread = new Thread(() -> {
            while (!Thread.currentThread().isInterrupted()) {
                // 执行任务
                System.out.println("Thread is running...");
                try {
                    Thread.sleep(1000);
                } catch (InterruptedException e) {
                    // 捕获到中断异常，设置中断标志位为true
                    Thread.currentThread().interrupt();
                }
            }
            System.out.println("Thread is interrupted and stopped.");
        });
        thread.start();

        // 主线程休眠3秒后中断子线程
        try {
            Thread.sleep(3000);
        } catch (InterruptedException e) {
            e.printStackTrace();
        }
        thread.interrupt();
    }
}
```

### 使用`stop`方法（已过时）
- **方法介绍**：`stop`方法用于强制终止线程。
- **原理**：它会立即停止线程的执行，并释放该线程所持有的所有锁。这种方式是不安全的，可能会导致数据不一致等问题，因为它不会给线程任何机会来清理资源或保存中间状态。所以在实际开发中，不建议使用该方法。
