### 1. `synchronized` 介绍
`synchronized` 是 Java 中的一个关键字，用于实现线程同步。它可以保证在同一时刻，只有一个线程能够访问被 `synchronized` 修饰的代码块或方法，从而避免多个线程同时访问共享资源时出现的数据不一致问题，确保线程安全。

`synchronized` 可以用于以下三种情况：
- **修饰实例方法**：锁的是当前实例对象，同一实例的不同线程在访问该方法时需要获取锁。
```java
public synchronized void method() {
    // 同步代码
}
```
- **修饰静态方法**：锁的是当前类的 `Class` 对象，不同实例的线程在访问该静态方法时也需要竞争同一把锁。
```java
public static synchronized void staticMethod() {
    // 同步代码
}
```
- **修饰代码块**：可以指定锁的对象，线程需要获取指定对象的锁才能进入该代码块。
```java
public void blockMethod() {
    synchronized (this) {
        // 同步代码
    }
}
```

### 2. `synchronized` 原理
在 Java 中，每个对象都有一个对象头（Object Header），其中的 Mark Word 部分存储了对象的锁状态等信息。`synchronized` 的底层实现依赖于对象头中的 Mark Word 和 Monitor（监视器）机制。

- **对象头与锁状态**：Mark Word 会根据锁的不同状态存储不同的信息，例如无锁状态、偏向锁状态、轻量级锁状态和重量级锁状态等。
- **Monitor 机制**：Monitor 是 Java 中实现同步的基础，每个 Java 对象都可以关联一个 Monitor。当一个线程尝试进入被 `synchronized` 修饰的代码块或方法时，它需要先获取该对象的 Monitor。如果 Monitor 已经被其他线程持有，那么该线程会被阻塞，直到持有 Monitor 的线程释放它。

### 3. `synchronized` 是否公平
`synchronized` 是非公平锁。非公平锁意味着线程获取锁的顺序并不一定是按照请求锁的先后顺序，后请求锁的线程有可能先获得锁。这样做的好处是可以减少线程上下文切换的开销，提高性能。例如，当一个持有锁的线程释放锁时，正好有一个新的线程请求该锁，那么这个新线程可能会直接获得锁，而不需要等待之前已经在等待的线程。

### 4. 锁升级
`synchronized` 锁的状态会随着竞争情况逐渐升级，升级过程为：无锁 -> 偏向锁 -> 轻量级锁 -> 重量级锁，且锁升级是单向的，不会降级。
- **偏向锁**：偏向锁的目的是在没有多线程竞争的情况下，减少锁的获取和释放带来的性能开销。当一个线程第一次访问同步块并获取锁时，会在对象头的 Mark Word 中记录该线程的 ID，以后该线程再次进入这个同步块时，无需进行任何同步操作，直接获取锁。只有当有其他线程尝试竞争该锁时，偏向锁才会撤销。
- **轻量级锁**：当多个线程交替访问同步块时，偏向锁会升级为轻量级锁。线程在进入同步块时，会在栈帧中创建一个锁记录（Lock Record），并尝试使用 CAS（Compare - And - Swap）操作将对象头的 Mark Word 复制到锁记录中，并将对象头的 Mark Word 指向锁记录。如果 CAS 操作成功，则线程获取到轻量级锁；如果失败，则表示有其他线程已经持有了锁，当前线程会进行自旋等待。
- **重量级锁**：如果自旋等待的线程数过多或者自旋时间过长，轻量级锁会升级为重量级锁。重量级锁依赖于操作系统的互斥量（Mutex），当线程获取不到锁时，会被阻塞并进入等待队列，由操作系统进行调度，这种方式会带来较大的性能开销。

### 5. CAS 自旋次数
在轻量级锁的情况下，当一个线程尝试获取锁失败时，会进行自旋操作，即不断地尝试使用 CAS 操作来获取锁，而不是立即阻塞。自旋次数并没有一个固定的值，JVM 会根据系统的运行情况进行自适应调整。早期的 JVM 中，自旋次数是固定的，例如 10 次；而在现代的 JVM 中，采用了自适应自旋锁，自旋的次数会根据上一次在同一个锁上的自旋时间以及锁的拥有者的状态来决定。如果在同一个锁上，线程自旋等待成功获得过锁，那么 JVM 会认为这次自旋也很可能成功，从而允许线程自旋更多次；反之，如果很少有自旋成功的情况，那么 JVM 可能会减少自旋次数甚至直接省略自旋过程，让线程进入阻塞状态。

### 6. 线程状态变化
当线程使用 `synchronized` 时，线程状态会发生如下变化：
- **初始状态**：线程处于 `NEW` 状态，即线程对象已经创建，但还没有调用 `start()` 方法。
- **可运行状态**：调用 `start()` 方法后，线程进入 `RUNNABLE` 状态，表示线程可以被 JVM 调度执行。
- **阻塞状态**：当线程尝试进入被 `synchronized` 修饰的代码块或方法，而锁已经被其他线程持有时，线程会进入 `BLOCKED` 状态，被放入锁的等待队列中，等待锁的释放。
- **可运行状态（再次）**：当持有锁的线程释放锁后，处于 `BLOCKED` 状态的线程会被唤醒，重新进入 `RUNNABLE` 状态，竞争锁。
- **终止状态**：线程执行完同步代码块或方法后，会继续执行后续代码，直到线程执行完毕，进入 `TERMINATED` 状态。

综上所述，`synchronized` 是 Java 中一种重要的线程同步机制，通过锁升级等策略在不同的竞争情况下提供了较好的性能表现。
