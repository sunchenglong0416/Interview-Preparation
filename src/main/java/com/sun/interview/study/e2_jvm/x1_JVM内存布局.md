| 内存模块 | 特性 | 作用 | 线程安全性 | 是否会发生内存泄露 | 是否会发生内存溢出 |
| --- | --- | --- | --- | --- | --- |
| 堆（Heap） | - 是 JVM 管理的最大内存区域<br>- 被所有线程共享<br>- 分为新生代和老年代，新生代又包含伊甸园区和幸存者区 | 存储对象实例和数组，是垃圾回收的主要区域 | 否，多线程访问需同步控制 | 是，如静态集合类持有对象引用、单例模式持有资源对象等 | 是，对象创建过多导致堆内存不足时会抛出 `OutOfMemoryError: Java heap space` |
| 方法区（元空间 Metaspace） | - 存储类信息、常量、静态变量等<br>- 使用本地内存，不使用 JVM 堆内存 | 存储类的元数据信息，支持类的加载、链接和初始化 | 是，多个线程可同时访问，由 JVM 管理同步 | 是，如动态生成大量类且未被卸载 | 是，当元空间达到最大容量时会抛出 `OutOfMemoryError: Metaspace` |
| 虚拟机栈（Java Virtual Machine Stacks） | - 每个线程有独立的虚拟机栈<br>- 每个方法执行时创建栈帧 | 描述 Java 方法执行的内存模型，存储局部变量表、操作数栈等信息 | 是，每个线程有自己的栈空间 | 否，方法执行结束栈帧自动弹出 | 是，当线程请求的栈深度超过虚拟机允许的最大深度时会抛出 `StackOverflowError`；若虚拟机栈可以动态扩展，当扩展时无法申请到足够内存会抛出 `OutOfMemoryError` |
| 本地方法栈（Native Method Stacks） | - 每个线程有独立的本地方法栈<br>- 为 Native 方法服务 | 存储 Native 方法的栈帧信息 | 是，每个线程有自己的本地方法栈 | 否，Native 方法执行结束栈帧自动弹出 | 是，与虚拟机栈类似，可能抛出 `StackOverflowError` 或 `OutOfMemoryError` |
| 程序计数器（Program Counter Register） | - 每个线程有独立的程序计数器<br>- 记录当前线程执行的字节码指令地址 | 作为当前线程所执行的字节码的行号指示器，控制程序执行流程 | 是，每个线程有自己的程序计数器 | 否，不会出现内存泄露问题 | 否，不会出现内存溢出问题 |
| 直接内存（Direct Memory） | - 不属 JVM 运行时数据区<br>- 通过 `ByteBuffer` 的 `allocateDirect()` 方法分配 | 提高 I/O 操作性能，避免 Java 堆和 Native 堆间的数据拷贝 | 否，需开发者自行管理同步 | 是，如未正确释放直接内存 | 是，当直接内存分配超过系统可用内存时会抛出 `OutOfMemoryError` |
