|引用类型|简介|垃圾回收时机|示例代码|特点及应用场景|
|--|--|--|--|--|
|强引用（Strong Reference）|最常见的引用类型，如`Object obj = new Object();`，`obj`就是一个强引用。只要强引用存在，对象就不会被垃圾回收。|只有当强引用被赋值为`null`，或者强引用变量超出作用域，且没有其他强引用指向该对象时，对象才会被垃圾回收器回收。|```java<br>Object obj = new Object();<br>obj = null; // 此时对象可能被垃圾回收<br>```|特点：对象只要有强引用关联，就永远不会被回收，能保证对象的生命周期。<br>应用场景：适用于程序中需要长期存在且必须保证存活的对象，如程序中的核心业务对象、单例模式中的实例等。|
|软引用（Soft Reference）|用`SoftReference`类表示，如`SoftReference<Object> softRef = new SoftReference<>(new Object());`。软引用关联的对象在系统将要发生内存溢出之前，会被垃圾回收器回收。|当 JVM 内存空间足够时，软引用对象不会被回收；当内存空间不足，且即将发生内存溢出时，系统会回收软引用指向的对象，以释放内存。|```java<br>SoftReference<Object> softRef = new SoftReference<>(new Object());<br>Object obj = softRef.get();<br>if (obj != null) {<br>    // 使用对象<br>} else {<br>    // 对象已被回收<br>}<br>```|特点：软引用可以让对象在内存充足时保持存在，内存紧张时被回收，用于实现缓存等场景，如网页图片缓存，先将图片以软引用的形式缓存，当内存不足时，缓存的图片可以被回收。<br>应用场景：适合用于实现内存敏感的缓存，在内存有压力时自动释放缓存对象。|
|弱引用（Weak Reference）|通过`WeakReference`类创建，如`WeakReference<Object> weakRef = new WeakReference<>(new Object());`。弱引用的对象只能生存到下一次垃圾回收之前，垃圾回收器工作时，无论内存是否充足，都会回收弱引用指向的对象。|在垃圾回收器进行垃圾回收操作时，只要发现弱引用指向的对象没有其他强引用关联，就会立即回收该对象。|```java<br>WeakReference<Object> weakRef = new WeakReference<>(new Object());<br>Object obj = weakRef.get();<br>if (obj != null) {<br>    // 使用对象<br>} else {<br>    // 对象已被回收<br>}<br>```|特点：弱引用的生命周期很短，对象随时可能被回收。<br>应用场景：常用于解决内存泄露问题，比如在集合类中使用弱引用，避免集合对对象的强引用导致对象无法被回收；也可用于一些临时对象的引用，这些对象不影响程序的核心逻辑，即使被回收也没关系。|
|虚引用（Phantom Reference）|使用`PhantomReference`类，如`PhantomReference<Object> phantomRef = new PhantomReference<>(new Object(), new ReferenceQueue<>());`。虚引用也称为幽灵引用或者幻影引用，它是最弱的一种引用关系。虚引用不会影响对象的生命周期，也无法通过虚引用来获取对象实例，它主要用于在对象被回收时收到一个通知。|当垃圾回收器准备回收一个对象时，如果发现它还有虚引用，就会在回收对象之后，把这个虚引用加入到与之关联的引用队列中。|```java<br>ReferenceQueue<Object> queue = new ReferenceQueue<>();<br>PhantomReference<Object> phantomRef = new PhantomReference<>(new Object(), queue);<br>Object obj = phantomRef.get(); // 始终为 null<br>```|特点：虚引用主要用于跟踪对象被垃圾回收的状态，无法通过虚引用访问对象实例。<br>应用场景：可用于对象回收时的一些清理工作，如资源释放的后续处理等；或者在一些需要监控对象生命周期结束的场景中使用。|
