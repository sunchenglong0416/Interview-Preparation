# redis 4.0 数据结构

Redis 4.0 中不同数据类型有各自的底层存储结构、扩容条件和应用场景，下面为你详细介绍：

### 字符串（String）
- **底层存储结构**
    - **int**：当存储的是可以用 64 位有符号整数表示的数值时，Redis 会使用 `int` 类型来存储，这样可以节省内存。
    - **embstr**：当存储的字符串长度小于等于 44 字节时，使用 `embstr` 编码。`embstr` 是一种紧凑的编码方式，它将 RedisObject 结构和 SDS（简单动态字符串）结构连续存储在一块内存中，减少了内存分配和释放的开销。
    - **raw**：当存储的字符串长度超过 44 字节时，使用 `raw` 编码。`raw` 编码会分别为 RedisObject 结构和 SDS 结构分配内存，SDS 结构可以动态扩展。
- **扩容条件**
    - 当存储的值从整数变为字符串，且字符串长度超过 44 字节时，`int` 编码会转换为 `raw` 编码；当存储的字符串长度从小于等于 44 字节变为超过 44 字节时，`embstr` 编码会转换为 `raw` 编码。
- **应用场景**
    - **缓存**：将数据库查询结果存储为字符串，下次查询时直接从 Redis 中获取，减少数据库压力。
    - **计数器**：利用 `INCR` 等命令对字符串类型的值进行原子性的自增或自减操作，可用于统计网站的访问量、文章的阅读量等。
    - **分布式锁**：使用 `SETNX`（SET if Not eXists）命令结合过期时间来实现简单的分布式锁。

### 哈希（Hash）
- **底层存储结构**
    - **ziplist**：当哈希对象保存的键值对数量少于 512 个（可通过 `hash - max - ziplist - entries` 配置），且每个键和值的长度都小于 64 字节（可通过 `hash - max - ziplist - value` 配置）时，使用 `ziplist` 编码。`ziplist` 是一种紧凑的列表结构，它将所有的键值对连续存储在一块内存中，节省内存空间。
    - **hashtable**：当哈希对象不满足 `ziplist` 的条件时，使用 `hashtable` 编码。`hashtable` 是一种哈希表结构，通过哈希函数将键映射到哈希表的槽位上，查找和插入操作的时间复杂度为 O(1)。
- **扩容条件**
    - 当哈希对象的键值对数量超过 `hash - max - ziplist - entries` 或者某个键值对的长度超过 `hash - max - ziplist - value` 时，`ziplist` 编码会转换为 `hashtable` 编码。
- **应用场景**
    - **存储对象**：可以将一个对象的各个属性存储为哈希表的键值对，方便对对象的属性进行单独的读写操作。例如，存储用户信息，每个用户的 ID 作为哈希表的键，用户的姓名、年龄、性别等属性作为哈希表的字段和值。
    - **缓存对象**：将数据库中的对象以哈希表的形式缓存到 Redis 中，减少数据库的查询次数。

### 列表（List）
- **底层存储结构**
    - **ziplist**：当列表对象保存的元素数量少于 512 个（可通过 `list - max - ziplist - entries` 配置），且每个元素的长度都小于 64 字节（可通过 `list - max - ziplist - value` 配置）时，使用 `ziplist` 编码。
    - **quicklist**：Redis 4.0 引入了 `quicklist` 作为列表的默认编码方式。`quicklist` 是由多个 `ziplist` 组成的双向链表，结合了 `ziplist` 节省内存和链表便于插入删除的优点。
- **扩容条件**
    - 当列表对象的元素数量超过 `list - max - ziplist - entries` 或者某个元素的长度超过 `list - max - ziplist - value` 时，`ziplist` 编码会转换为 `quicklist` 编码。
- **应用场景**
    - **消息队列**：使用 `LPUSH` 和 `RPOP` 命令可以实现简单的先进先出（FIFO）队列，用于异步处理任务。
    - **栈**：使用 `LPUSH` 和 `LPOP` 命令可以实现后进先出（LIFO）栈。
    - **最新消息列表**：使用 `LPUSH` 命令将新消息添加到列表头部，然后使用 `LRANGE` 命令获取最新的消息列表。

### 集合（Set）
- **底层存储结构**
    - **intset**：当集合对象保存的所有元素都是整数值，且元素数量少于 512 个（可通过 `set - max - intset - entries` 配置）时，使用 `intset` 编码。`intset` 是一种整数集合，它将所有的整数元素按从小到大的顺序存储在一块连续的内存中，通过二分查找来提高查找效率。
    - **hashtable**：当集合对象不满足 `intset` 的条件时，使用 `hashtable` 编码。`hashtable` 中的键为集合的元素，值都为 `NULL`。
- **扩容条件**
    - 当集合对象的元素数量超过 `set - max - intset - entries` 或者某个元素不是整数值时，`intset` 编码会转换为 `hashtable` 编码。
- **应用场景**
    - **去重**：利用集合元素的唯一性，对数据进行去重处理。
    - **交集、并集、差集运算**：可以使用 Redis 提供的 `SINTER`、`SUNION`、`SDIFF` 等命令对多个集合进行交集、并集、差集运算，用于社交网络中的共同好友、推荐系统等场景。
    - **随机抽取**：使用 `SRANDMEMBER` 或 `SPOP` 命令可以从集合中随机抽取元素，可用于抽奖等场景。

### 有序集合（Sorted Set）
- **底层存储结构**
    - **ziplist**：当有序集合对象保存的元素数量少于 128 个（可通过 `zset - max - ziplist - entries` 配置），且每个元素的长度都小于 64 字节（可通过 `zset - max - ziplist - value` 配置）时，使用 `ziplist` 编码。在 `ziplist` 中，每个元素和它的分数依次存储。
    - **skiplist + hashtable**：当有序集合对象不满足 `ziplist` 的条件时，使用 `skiplist + hashtable` 编码。`skiplist` 是一种跳跃表，它可以在 O(log n) 的时间复杂度内完成插入、删除和查找操作；`hashtable` 用于快速查找元素的分数。
- **扩容条件**
    - 当有序集合对象的元素数量超过 `zset - max - ziplist - entries` 或者某个元素的长度超过 `zset - max - ziplist - value` 时，`ziplist` 编码会转换为 `skiplist + hashtable` 编码。
- **应用场景**
    - **排行榜**：根据元素的分数对元素进行排序，可用于游戏排行榜、文章热度排行榜等场景。
    - **范围查找**：使用 `ZRANGE`、`ZREVRANGE` 等命令可以根据分数范围或排名范围查找元素，适用于查找热门商品、热门文章等。

### 有序集合（Sorted Set） 跳表插入数据和查询数据的过程
当然，可以详细解释 Redis 中有序集合（Sorted Set）的底层存储结构——跳跃表（Skip List），以及跳跃表中插入数据和查询数据的过程。

### 1. 跳跃表（Skip List）简介

**定义**：
跳跃表是一种随机化的数据结构，用于实现有序集合。跳跃表通过多层链表来加速查找、插入和删除操作，类似于平衡树（如 AVL 树、红黑树），但实现更简单且性能优异。

**特点**：
- **有序性**：跳跃表中的元素按顺序排列。
- **高效性**：查找、插入和删除操作的时间复杂度为 O(log n)。
- **随机化**：通过随机化层数来保持平衡，避免最坏情况。
- **内存效率**：相比于平衡树，跳跃表的内存使用更高效。

### 2. 跳跃表的结构

跳跃表由多层链表组成，每一层链表中的节点包含指向同一层的下一个节点和下一层的节点指针。跳跃表的顶层链表包含较少的节点，用于快速跳过大量节点，底层链表包含所有节点，用于精确查找。

**示例结构**：
假设一个跳跃表包含以下元素：`10:A`, `20:B`, `30:C`, `40:D`, `50:E`。

```
Level 3: 10:A ----------------------> 50:E ----------------------> NULL
Level 2: 10:A ----------------------> 30:C ----------------------> 50:E ----------------------> NULL
Level 1: 10:A ----------> 20:B ----------> 30:C ----------> 40:D ----------> 50:E ----------> NULL
Level 0: 10:A ---> 20:B ---> 30:C ---> 40:D ---> 50:E ---> NULL
```


### 3. 插入数据的过程

**步骤**：
1. **查找插入位置**：从顶层链表开始，逐层向下查找插入位置。
2. **随机化层数**：为新节点随机生成层数。
3. **插入节点**：在确定的层数中插入新节点。

**详细过程**：

1. **查找插入位置**：
    - 从顶层链表的头节点开始，逐层向下查找插入位置。
    - 在每一层中，找到小于新节点的最后一个节点，记录该节点为当前层的前驱节点。
    - 逐层向下，直到到达底层链表。

2. **随机化层数**：
    - 为新节点随机生成层数。Redis 使用一种概率算法来决定新节点的层数。
    - 概率算法：新节点的层数为 1 的概率为 1/4，层数为 2 的概率为 1/16，层数为 3 的概率为 1/64，依此类推。

3. **插入节点**：
    - 在确定的层数中插入新节点。
    - 更新前驱节点的指针，将新节点插入到链表中。
    - 如果新节点的层数超过当前最大层数，更新跳跃表的最大层数。

**示例**：
假设要插入元素 `25:F`。

1. **查找插入位置**：
    - 从顶层链表开始，找到小于 `25` 的最后一个节点 `10:A`。
    - 逐层向下，直到到达底层链表。

2. **随机化层数**：
    - 为新节点 `25:F` 随机生成层数，假设生成的层数为 2。

3. **插入节点**：
    - 在第 2 层和第 1 层插入新节点 `25:F`。
    - 更新前驱节点的指针，将新节点插入到链表中。

**插入后的结构**：
```
Level 3: 10:A ----------------------> 50:E ----------------------> NULL
Level 2: 10:A ----------------------> 25:F ----------------------> 50:E ----------------------> NULL
Level 1: 10:A ----------> 20:B ----------> 25:F ----------> 30:C ----------> 40:D ----------> 50:E ----------> NULL
Level 0: 10:A ---> 20:B ---> 25:F ---> 30:C ---> 40:D ---> 50:E ---> NULL
```


### 4. 查询数据的过程

**步骤**：
1. **查找目标节点**：从顶层链表开始，逐层向下查找目标节点。
2. **返回结果**：找到目标节点后，返回其值和分数。

**详细过程**：

1. **查找目标节点**：
    - 从顶层链表的头节点开始，逐层向下查找目标节点。
    - 在每一层中，找到小于或等于目标节点的最后一个节点，记录该节点为当前层的前驱节点。
    - 逐层向下，直到到达底层链表。

2. **返回结果**：
    - 在底层链表中查找目标节点。
    - 找到目标节点后，返回其值和分数。

**示例**：
假设要查询元素 `30:C`。

1. **查找目标节点**：
    - 从顶层链表开始，找到小于或等于 `30` 的最后一个节点 `25:F`。
    - 逐层向下，直到到达底层链表。

2. **返回结果**：
    - 在底层链表中查找目标节点 `30:C`。
    - 找到目标节点后，返回其值 `C` 和分数 `30`。

**查询过程**：
```

Level 2: 10:A ----------------------> 25:F ----------------------> 50:E ----------------------> NULL
Level 1: 10:A ----------> 20:B ----------> 25:F ----------> 30:C ----------> 40:D ----------> 50:E ----------> NULL
```

### 8. 跳跃表的插入和查询过程的算法

#### 8.1 插入算法

**伪代码**：
```pseudo
function insert(x, score):
    // 创建一个新节点，随机生成层数
    node = createNode(x, score, randomLevel())
    
    // 创建一个更新数组，记录每一层的前驱节点
    update = array of NULL
    
    // 从顶层链表开始，逐层向下查找插入位置
    current = head
    for level = maxLevel downto 0:
        while current.next[level] != NULL and current.next[level].score < score:
            current = current.next[level]
        update[level] = current
    
    // 在确定的层数中插入新节点
    for level = 0 to node.level:
        node.next[level] = update[level].next[level]
        update[level].next[level] = node
    
    // 如果新节点的层数超过当前最大层数，更新跳跃表的最大层数
    if node.level > maxLevel:
        for level = maxLevel + 1 to node.level:
            update[level] = head
            head.next[level] = node
        maxLevel = node.level
```


**解释**：
1. **创建新节点**：创建一个新节点 `node`，随机生成层数。
2. **查找插入位置**：从顶层链表开始，逐层向下查找插入位置，记录每一层的前驱节点。
3. **插入节点**：在确定的层数中插入新节点，更新前驱节点的指针。
4. **更新最大层数**：如果新节点的层数超过当前最大层数，更新跳跃表的最大层数。

#### 8.2 查询算法

**伪代码**：
```pseudo
function search(score):
    // 从顶层链表开始，逐层向下查找目标节点
    current = head
    for level = maxLevel downto 0:
        while current.next[level] != NULL and current.next[level].score < score:
            current = current.next[level]
    
    // 在底层链表中查找目标节点
    current = current.next[0]
    if current != NULL and current.score == score:
        return current.value, current.score
    else:
        return NULL
```


**解释**：
1. **查找目标节点**：从顶层链表开始，逐层向下查找目标节点，记录每一层的前驱节点。
2. **返回结果**：在底层链表中查找目标节点，找到目标节点后返回其值和分数；否则返回 `NULL`。
