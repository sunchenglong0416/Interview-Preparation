### 原理
布隆过滤器由一个位数组（bit - array）和多个相互独立的哈希函数组成。初始时，位数组所有位被置为0 。当添加元素时，元素通过k个哈希函数计算，映射到位数组的k个位置，将这些位置的值设为1。判断元素是否存在时，同样用k个哈希函数计算位置，若对应位置都为1，则认为元素可能存在；若有一个位置为0，则元素一定不存在。

### 应用场景
- **缓存穿透防范**：在分布式缓存系统中，拦截不存在数据的查询，避免请求直达数据库，减轻数据库压力。如Redis前部署布隆过滤器，先判断数据是否存在，不存在则直接返回，不查询数据库。
- **URL去重**：爬虫系统中，判断已爬取URL，防止重复爬取相同网址，减少无效网络请求与数据处理。
- **垃圾邮件过滤**：存储已知垃圾邮件特征信息，新邮件到达时，快速判断是否为垃圾邮件，提升过滤效率。
- **数据库查询优化**：判断数据库中特定记录（如用户ID）是否存在，不存在则无需执行实际查询操作，加速查询。
- **分布式系统数据共享**：不同节点共享布隆过滤器，判断元素是否在全局数据集合，减少节点间网络通信。

### 优点
- **空间效率高**：通过位数组和哈希函数映射，相比传统存储集合元素方式，极大节省存储空间。
- **查询速度快**：插入和查询操作主要是计算哈希函数，时间复杂度为常数O(k)（k为哈希函数个数） ，能快速给出判断结果。
- **易于硬件实现**：哈希函数相互独立，方便硬件并行计算，提升性能。
- **隐私保护**：不存储元素实际值，无法从中获取原始数据，一定程度保护数据隐私。

### 缺点
- **存在误判率**：会出现假阳性（False Positive），即误判原本不在集合中的元素为存在。随元素增多，误判概率增大。
- **元素删除困难**：普通布隆过滤器难以安全删除元素。删除一个元素对应比特位，可能影响其他元素映射，导致误判率大幅上升。 增强型布隆过滤器虽可实现删除，但实现复杂。
- **准确性受限**：只能判断元素可能存在或一定不存在，不能确切证明元素存在。

### 判断一定不存在误差率产生原因
布隆过滤器判断元素一定不存在理论上不会出错，但实际存在极小误差率，原因如下：
- **哈希函数特性**：哈希函数虽尽可能均匀分布，但仍可能将不同元素映射到相同比特位。极端情况下，某元素经哈希计算的位置，恰好因其他元素已全被置为1 ，就会使原本不存在的元素被误判为存在。
- **哈希冲突累积**：随着元素不断加入，哈希冲突概率增加，更多比特位被置为1。即使新元素与已有元素不同，也更易因这些已被占用的比特位被误判。
