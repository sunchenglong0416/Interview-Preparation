

|问题|概念描述|发生场景|解决方案|
|--|--|--|--|
|缓存穿透|指查询一个不存在的数据，由于缓存中没有，会直接查询数据库，若有大量这样的请求，就会导致数据库压力过大甚至崩溃。|恶意攻击，如黑客故意大量访问不存在的键；业务中对数据的校验不严格，导致出现不合理的查询请求。|对查询结果为空的情况也进行缓存，设置较短的过期时间；使用布隆过滤器，在查询缓存前先判断数据是否存在，不存在则直接返回，避免查询数据库。|
|缓存击穿|指缓存中某个热点 key 过期的瞬间，大量并发请求同时访问该 key，导致这些请求直接打到数据库，造成数据库压力骤增。|一般是热点数据，如秒杀活动中的商品信息、热门新闻等，当缓存过期时，大量并发请求同时访问该数据。|使用互斥锁，在缓存过期时，只允许一个线程去查询数据库并更新缓存，其他线程等待；延长热点数据的缓存过期时间，或者设置永不过期，定期在后台更新数据。|
|缓存雪崩|指在同一时刻，大量的缓存 key 同时过期，导致大量请求直接访问数据库，使数据库压力过大，甚至可能导致数据库崩溃，进而影响整个系统的正常运行。|缓存设置了相同的过期时间，例如一批数据都是在某个时间点统一缓存，且过期时间相同；或者缓存服务器故障，导致所有缓存数据丢失。|为缓存设置不同的过期时间，避免大量 key 同时过期；采用多级缓存架构，如本地缓存 + 分布式缓存，当分布式缓存失效时，可先从本地缓存获取数据；对缓存数据进行持久化，以便在缓存服务器重启后能快速恢复数据。|
