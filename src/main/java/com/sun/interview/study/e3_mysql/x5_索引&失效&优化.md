MySQL索引是帮助MySQL高效获取数据的数据结构，常见的索引分类及各类索引的失效情况如下：

### 索引分类
- **普通索引**：最基本的索引类型，没有任何限制，用于加速数据的查询。创建语法：`CREATE INDEX index_name ON table_name (column_name);`。
- **唯一索引**：索引列中的值必须唯一，但允许有空值。如果是组合唯一索引，则列值的组合必须唯一。创建语法：`CREATE UNIQUE INDEX index_name ON table_name (column_name);`。
- **主键索引**：特殊的唯一索引，用于唯一标识表中的每一行数据，不允许有空值。一个表只能有一个主键索引。创建语法：`ALTER TABLE table_name ADD PRIMARY KEY (column_name);`。
- **组合索引**：也叫联合索引，是在多个列上创建的索引。MySQL会根据索引中列的顺序来使用索引。创建语法：`CREATE INDEX index_name ON table_name (column1, column2, ...);`。
- **全文索引**：用于在文本类型的列上进行全文搜索，能快速查找包含特定关键词的文本。创建语法：`CREATE FULLTEXT INDEX index_name ON table_name (column_name);`。

### 索引失效情况
- **普通索引、唯一索引、主键索引、组合索引**
    - **数据类型不一致**：如果查询条件中的列数据类型与索引列的数据类型不一致，可能导致索引失效。例如，索引列是 `INT` 类型，而查询时使用了字符串类型进行比较。
    - **函数使用**：在索引列上使用函数，MySQL通常无法使用索引。例如，`SELECT * FROM table WHERE YEAR(date_column) = 2024;`，`YEAR()` 函数会使 `date_column` 上的索引失效。
    - **表达式计算**：如果查询条件中包含对索引列的表达式计算，索引可能失效。如 `SELECT * FROM table WHERE column + 1 = 5;`，应该改为 `SELECT * FROM table WHERE column = 4;`。
    - **范围查询后的列**：在组合索引中，如果范围查询（如 `>`、`<`、`BETWEEN` 等）使用了索引中的某一列，那么该列后面的列在查询中无法使用索引优化。例如，有组合索引 `(col1, col2, col3)`，查询 `SELECT * FROM table WHERE col1 = 'value1' AND col2 > 'value2' AND col3 = 'value3';`，`col3` 无法使用索引。
    - **`OR` 条件**：当 `OR` 连接的条件中有一个列没有索引，那么整个查询可能无法使用索引。例如，`SELECT * FROM table WHERE col1 = 'value1' OR col2 = 'value2';`，如果 `col2` 没有索引，`col1` 上的索引可能也不会被使用。
    - **`LIKE` 以通配符开头**：如果 `LIKE` 条件以通配符开头，如 `SELECT * FROM table WHERE column LIKE '%value';`，索引将失效。但如果是 `LIKE 'value%'`，则可以使用索引。
- **全文索引**
    - **停用词**：全文索引会忽略一些常见的停用词，如 `the`、`a`、`an` 等。如果查询中只包含停用词，将无法使用全文索引进行搜索。
    - **非文本类型列**：全文索引只能用于文本类型的列，如果在非文本类型列上创建全文索引，或者查询时使用非文本类型列进行全文搜索，索引将失效。
    - **查询语句不支持**：如果查询语句的语法不符合全文索引的使用规则，例如使用了不支持的操作符或函数，索引将无法正常使用。不同的存储引擎对全文索引的支持和语法略有不同，需要根据具体情况进行正确的查询编写。
-  **组合索引-失效**
- ### 组合索引的底层存储
在 MySQL 的 InnoDB 存储引擎中，组合索引（联合索引）底层基于 B+ 树数据结构来存储，下面详细介绍其存储方式：

#### 索引键排序
组合索引会将多个列组合成一个索引键，并且按照这些列的顺序进行排序。例如，对于一个包含列 `(col1, col2, col3)` 的组合索引，B+ 树会先按照 `col1` 的值进行排序，如果 `col1` 的值相同，再按照 `col2` 的值排序，若 `col2` 的值也相同，最后按照 `col3` 的值排序。

#### B+ 树结构
- **非叶子节点**：存储索引键和指向子节点的指针。索引键由组合索引中的列值组成。通过这些索引键和指针，B+ 树能够快速定位到叶子节点。
- **叶子节点**：存储完整的索引键和对应的主键值（如果是二级索引）。叶子节点之间通过指针相连，形成一个有序链表，方便进行范围查询。

### 最左匹配原则失效的原因
最左匹配原则指的是在组合索引中，MySQL 会从索引的最左列开始匹配，只有当最左列被使用时，索引才可能被使用。以下是最左匹配原则失效的常见原因：

#### 1. 跳过最左列
如果查询语句中没有使用组合索引的最左列，那么整个组合索引将无法被使用。例如，对于组合索引 `(col1, col2, col3)`，查询语句 `SELECT * FROM table WHERE col2 = 'value2' AND col3 = 'value3';` 由于没有使用 `col1`，无法利用该组合索引。

#### 2. 范围查询中断后续列的使用
当组合索引中某一列使用了范围查询（如 `>`、`<`、`BETWEEN` 等），该列之后的列无法使用索引进行优化。例如，对于组合索引 `(col1, col2, col3)`，查询语句 `SELECT * FROM table WHERE col1 = 'value1' AND col2 > 'value2' AND col3 = 'value3';` 中，`col2` 使用了范围查询，`col3` 无法使用索引。

#### 3. 函数或表达式操作
如果在组合索引的列上使用了函数或表达式，会导致索引失效。例如，对于组合索引 `(col1, col2)`，查询语句 `SELECT * FROM table WHERE UPPER(col1) = 'VALUE1' AND col2 = 'value2';` 中，`UPPER(col1)` 使 `col1` 上的索引无法使用，进而影响整个组合索引的使用。

#### 4. 数据类型不匹配
当查询条件中的列数据类型与索引列的数据类型不一致时，可能导致索引失效。例如，索引列 `col1` 是 `INT` 类型，而查询语句中使用字符串类型进行比较 `SELECT * FROM table WHERE col1 = '1';`，可能会使组合索引无法使用。

#### 5. `OR` 条件连接
如果查询条件使用 `OR` 连接，且其中有列不在组合索引的最左连续部分，可能会导致最左匹配原则失效。例如，对于组合索引 `(col1, col2)`，查询语句 `SELECT * FROM table WHERE col1 = 'value1' OR col3 = 'value3';` 由于 `col3` 不在组合索引中，可能无法使用该组合索引。

# 回表
在MySQL中，回表是指在使用索引查询时，先通过索引找到满足条件的记录的主键值，然后再根据主键值去聚簇索引（通常是主键索引）中查询完整的记录信息。以下是一些避免回表的方法：
- **使用覆盖索引**：覆盖索引是指查询所需要的所有列都包含在索引中，这样查询时就可以直接从索引中获取数据，而不需要回表查询。例如，对于查询语句`SELECT name, age FROM users WHERE age > 18`，如果在`age`列上有索引，并且`name`和`age`列都包含在索引中，那么就可以使用覆盖索引来避免回表。可以通过创建联合索引`CREATE INDEX idx_age_name ON users (age, name)`来实现覆盖索引。
- **合理设计索引**：根据查询语句的条件和需要返回的列，设计合适的索引。尽量将经常用于查询条件和结果集的列包含在索引中。同时，要注意索引的选择性，选择性越高，索引的效果越好。例如，对于一个性别列，其值只有`男`和`女`两种，选择性较低，不太适合单独作为索引列。
- **避免不必要的列查询**：只查询需要的列，而不是使用`SELECT *`。如果查询中只需要少数几列，那么可以将这些列包含在索引中，从而避免回表查询所有列。
- **优化查询语句**：检查查询语句的逻辑，确保查询条件能够有效地利用索引。例如，避免在索引列上使用函数或表达式，因为这可能会导致索引失效，从而引发回表。另外，尽量使用等值查询、范围查询等能够利用索引的查询条件。
- **使用索引提示**：在某些情况下，可以使用索引提示来告诉MySQL使用特定的索引，以避免回表。例如，`SELECT * FROM users USE INDEX (idx_age) WHERE age > 18`，通过`USE INDEX`提示指定使用`idx_age`索引。不过，索引提示需要谨慎使用，因为MySQL的查询优化器通常能够自动选择合适的索引，不正确的索引提示可能会导致性能下降。
