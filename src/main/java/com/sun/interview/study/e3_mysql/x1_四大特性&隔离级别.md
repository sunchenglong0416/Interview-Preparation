### MySQL 四大特性（ACID）

#### 1. 原子性（Atomicity）
- **定义**：原子性是指一个事务中的所有操作，要么全部完成，要么全部不完成，不会停留在中间某个环节。如果事务在执行过程中发生错误，会被回滚到事务开始前的状态，就像这个事务从来没有执行过一样。
- **示例**：在银行转账操作中，从账户 A 向账户 B 转账 100 元，这个事务包含两个操作：从账户 A 扣除 100 元，向账户 B 增加 100 元。这两个操作必须作为一个整体来执行，要么都成功，要么都失败。如果在扣除账户 A 的 100 元后，系统出现故障，那么这 100 元会被回滚到账户 A，保证数据的一致性。

#### 2. 一致性（Consistency）
- **定义**：一致性是指事务执行前后，数据库的数据必须保持一致状态。也就是说，事务的执行不能破坏数据库的完整性约束，如主键约束、唯一约束等。
- **示例**：在一个学生信息表中，学生的学号必须是唯一的。如果一个事务试图插入两条学号相同的记录，那么这个事务会失败，因为它破坏了学号的唯一约束，数据库会保证数据的一致性。

#### 3. 隔离性（Isolation）
- **定义**：隔离性是指多个事务并发执行时，一个事务的执行不能被其他事务干扰。即一个事务内部的操作及使用的数据对其他并发事务是隔离的，并发执行的各个事务之间不能互相干扰。
- **示例**：假设有两个事务同时对一个账户进行操作，一个事务进行存款操作，另一个事务进行取款操作。隔离性保证了这两个事务不会互相影响，每个事务都能独立地完成自己的操作。

#### 4. 持久性（Durability）
- **定义**：持久性是指一个事务一旦提交，它对数据库中数据的改变就应该是永久性的。即使数据库发生故障，如系统崩溃、磁盘损坏等，已经提交的事务的数据也不会丢失。
- **示例**：当一个用户在网上购物完成支付后，支付成功的记录会被永久保存到数据库中。即使数据库服务器突然断电，在恢复后，该支付记录仍然存在。

### MySQL 隔离级别

#### 1. 读未提交（Read Uncommitted）
- **定义**：在该隔离级别下，一个事务可以读取另一个未提交事务的数据。这是最低的隔离级别，会导致脏读、不可重复读和幻读等问题。
- **问题示例**：
    - **脏读**：事务 A 修改了一条记录，但还未提交，事务 B 读取了这个未提交的数据。如果事务 A 随后回滚，那么事务 B 读取的数据就是无效的，这就是脏读。

#### 2. 读已提交（Read Committed）
- **定义**：一个事务只能读取另一个已经提交事务的数据。这种隔离级别可以避免脏读问题，但仍然可能出现不可重复读和幻读问题。
- **问题示例**：
    - **不可重复读**：事务 A 多次读取同一条记录，在事务 A 执行期间，事务 B 修改了这条记录并提交。那么事务 A 两次读取到的数据可能不一样，这就是不可重复读。

#### 3. 可重复读（Repeatable Read）
- **定义**：在同一个事务中，多次读取同一数据的结果是一致的。MySQL 的 InnoDB 存储引擎默认的隔离级别就是可重复读。它可以避免脏读和不可重复读问题，但仍然可能出现幻读问题。
- **问题示例**：
    - **幻读**：事务 A 按照一定的条件查询数据，在事务 A 执行期间，事务 B 插入了符合该条件的新记录并提交。当事务 A 再次按照相同条件查询时，会发现多了一些记录，就像出现了幻觉一样，这就是幻读。不过，InnoDB 存储引擎通过使用间隙锁（Gap Lock）等机制，在可重复读隔离级别下可以有效避免幻读问题。

#### 4. 串行化（Serializable）
- **定义**：这是最高的隔离级别，它会强制事务串行执行，即一个事务执行完后，另一个事务才能开始执行。这种隔离级别可以避免脏读、不可重复读和幻读问题，但会导致并发性能下降。
- **示例**：在这种隔离级别下，如果有两个事务同时对一个表进行操作，其中一个事务会被阻塞，直到另一个事务执行完毕。

以下是查看和设置 MySQL 隔离级别的 SQL 语句：
```sql
-- 查看当前会话的隔离级别
SELECT @@tx_isolation;

-- 设置当前会话的隔离级别为读已提交
SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;
```
