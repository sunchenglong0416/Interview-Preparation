对称密钥和非对称密钥的区别
- **密钥数量**
    - 对称密钥：加密和解密使用同一把密钥。
    - 非对称密钥：使用一对密钥，公钥公开，用于加密或验证签名；私钥保密，用于解密或生成签名。
- **安全性**
    - 对称密钥：密钥需在通信双方安全共享，一旦泄露，加密信息易被破解。
    - 非对称密钥：公钥公开，私钥由用户保管，仅知公钥难以推导出私钥，安全性较高。
- **加密速度**
    - 对称密钥：加密和解密速度快，适合大量数据加密。
    - 非对称密钥：因复杂数学运算，加密和解密速度慢，不适合大量数据加密。
- **用途**
    - 对称密钥：常用于数据加密、文件加密等，如网络通信中加密传输数据。
    - 非对称密钥：主要用于数字签名、密钥交换、身份验证，如SSL/TLS协议建立安全连接。

对称密钥和非对称密钥的原理
- **对称密钥**：
  通信双方使用相同密钥对数据进行加密和解密，加密和解密过程基于特定的数学算法，如置换、代换等操作，对数据进行变换，使明文变为密文，密文在接收端通过相同密钥和逆操作还原为明文。
- **非对称密钥**：
  基于数学难题，如RSA算法基于大整数分解难题，ECC算法基于椭圆曲线离散对数难题。公钥和私钥在数学上相关但难以从公钥推算出私钥。加密时，用公钥对明文进行运算得到密文；解密时，用私钥对密文进行特定运算还原出明文。
  数字签名则是用私钥对消息摘要进行运算生成签名，用公钥验证签名的合法性。

对称密钥和非对称密钥的常见算法
- **对称密钥算法**
    - **DES（Data Encryption Standard）**：分组加密算法，将明文分成64位分组，使用56位密钥对其加密，通过一系列置换、代换操作实现加密。
    - **3DES（Triple DES）**：对DES的改进，使用三个不同密钥对数据进行三次DES加密，增强了安全性，但速度较慢。
    - **AES（Advanced Encryption Standard）**：取代DES的标准对称加密算法，支持128位、192位和256位密钥长度，将明文分成128位分组，通过字节替换、行移位、列混淆和轮密钥加等操作进行加密，安全性高且速度快。
- **非对称密钥算法**
    - **RSA**：由罗纳德·李维斯特、阿迪·萨莫尔和伦纳德·阿德曼三人提出，基于大整数分解难题。公钥和私钥通过选择两个大素数相乘等一系列运算生成，加密和解密基于模幂运算。
    - **DSA（Digital Signature Algorithm）**：主要用于数字签名，基于离散对数问题，通过生成随机数、计算签名值等步骤生成签名，验证时通过公钥和相关参数验证签名的有效性。
    - **ECC（Elliptic Curve Cryptography）**：基于椭圆曲线离散对数难题，相比RSA等算法，在相同安全强度下，ECC密钥长度更短，计算量和存储空间更小，适用于资源受限设备。

防串改算法及其原理
- **消息认证码（MAC，Message Authentication Code）**
    - **原理**：使用密钥和特定算法对消息进行运算，生成一个固定长度的认证码。接收方用相同密钥和算法对接收消息进行运算，将得到的认证码与发送方的认证码对比，若一致则消息未被篡改。常见算法有HMAC（基于哈希的消息认证码），它结合了哈希函数和密钥，通过在哈希运算中加入密钥来保证消息完整性和认证。
- **数字签名**
    - **原理**：发送方用私钥对消息摘要进行加密生成数字签名，与消息一起发送给接收方。接收方用发送方公钥对数字签名解密得到消息摘要，同时对接收消息生成摘要，对比两个摘要，若相同则消息未被篡改且来源可靠。如RSA数字签名，先对消息进行哈希运算得到摘要，再用私钥对摘要加密。
- **哈希算法**
    - **原理**：将任意长度的数据映射为固定长度的哈希值。无论数据大小，相同数据的哈希值始终相同，不同数据的哈希值几乎不同。通过对比数据的哈希值判断数据是否被篡改。常见哈希算法有MD5、SHA-1、SHA-256等。但MD5和SHA-1存在碰撞概率，安全性不如SHA-256等高安全性哈希算法。

防串改算法通过使用密钥、数字签名或哈希值等方式，为数据提供完整性验证和来源认证，确保数据在传输和存储过程中不被非法篡改。
