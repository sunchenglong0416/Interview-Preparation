以下是关于ES 7.0更详细的介绍：

### ES 7.0简介
Elasticsearch 7.0是一款开源的分布式、高扩展、高可用的搜索和数据分析引擎。它基于Lucene构建，能高效处理大规模的结构化和非结构化数据，提供近实时的搜索和分析功能，广泛应用于信息检索、日志分析、业务智能等领域。

### 核心组件
- **节点**：集群中的服务器，分为Master节点、Data节点、Coordinating节点等，承担不同角色和任务。
- **索引**：是具有相同结构的文档集合，类似数据库中的表。
- **分片**：索引可拆分为多个分片，分布在不同节点上，实现分布式存储和并行处理。
- **副本**：每个分片可以有多个副本，用于数据冗余和提高系统的可用性与查询性能。
- **Lucene**：底层的全文检索库，提供了强大的文本处理和索引功能。

### 索引字段类型选择
- **文本类型（text）**：用于存储大量文本数据，如文章内容、产品描述等，会进行分词处理以支持全文搜索。
- **关键字类型（keyword）**：适用于精确匹配的字段，如身份证号、邮政编码、标签等，不会分词，常用于过滤、排序和聚合操作。
- **数值类型（number）**：包括各种整数和浮点数类型，用于存储数值数据，方便进行数值计算和范围查询。
- **日期类型（date）**：用于存储日期和时间数据，支持多种日期格式，便于进行日期范围查询和时间序列分析。
- **布尔类型（boolean）**：存储布尔值，用于表示逻辑状态，如是否激活、是否删除等。
- **对象类型（object）**：用于存储复杂的嵌套数据结构，如包含多个属性的JSON对象。

### 最小高可用集群搭建对机器和内存的要求
- **机器要求**：建议采用至少3台服务器作为节点，以实现高可用性和数据冗余。服务器应具备稳定的网络连接、足够的磁盘空间和多核处理器，以支持ES的并发处理能力。
- **内存要求**：一般来说，每台服务器的内存配置应根据数据量和业务需求来确定。对于小型集群，每台服务器至少配备8GB内存；对于中型集群，16 - 32GB内存较为合适；对于大型集群，每台服务器可配置64GB及以上内存。同时，要为操作系统和其他必要进程预留一定的内存空间。

### 确定Master节点及Master节点挂了的处理方法
- **确定Master节点**：在ES集群中，节点启动时会通过分布式选举算法（如Zen Discovery）来选举Master节点。具有最高版本号的节点、具有最多集群状态信息的节点或符合特定选举规则（如节点ID顺序等）的节点会被选举为Master节点。Master节点负责管理集群的元数据，如索引的创建、删除，节点的加入、离开等。
- **Master节点挂了的处理**：当Master节点挂掉后，集群会自动触发重新选举流程。其他节点会根据选举算法重新选举出一个新的Master节点。在选举过程中，集群可能会短暂处于不稳定状态，部分操作可能会被阻塞，直到新的Master节点选举出来并恢复正常的集群管理。为了确保集群的高可用性，建议配置多个候选Master节点，以提高选举的成功率和集群的稳定性。

### 设置分片
- **考虑因素**：设置分片时需要综合考虑数据量、查询模式、集群规模和性能要求等因素。一般原则是，数据量越大，需要的分片越多，以实现数据的均匀分布和并行处理。同时，要避免分片过多导致管理成本过高和性能下降。
- **示例**：对于一个预计存储1TB数据的索引，假设平均每个分片可存储100GB数据，那么可以考虑设置10个主分片。如果集群有5台数据节点，每个节点可分配2个主分片。副本分片数量通常根据对数据可用性和查询性能的要求来设置，一般设置1 - 2个副本分片即可。

### 扩容及对性能的影响
- **扩容方法**：通过向集群中添加新的节点来实现扩容。新节点加入后，ES会自动进行数据重新分配和负载均衡，将部分分片从现有节点迁移到新节点上，以实现数据的均匀分布。
- **对性能的影响**：扩容过程中，由于数据迁移和集群状态的调整，可能会导致短期内系统性能下降，如查询响应时间变长、写入性能降低等。但扩容完成后，随着集群资源的增加，系统的整体性能和可扩展性会得到提升，能够处理更多的数据和更高的并发请求。

### 通过curl操作索引
- **创建索引**
```bash
curl -X PUT "http://localhost:9200/my_index" -H 'Content-Type: application/json' -d '
{
  "settings": {
    "number_of_shards": 3,
    "number_of_replicas": 1
  },
  "mappings": {
    "properties": {
      "field1": { "type": "text" },
      "field2": { "type": "keyword" },
      "field3": { "type": "integer" }
    }
  }
}'
```
- **查询索引**
```bash
curl -X GET "http://localhost:9200/my_index/_search?q=field1:value"
```
- **更新索引**
```bash
curl -X POST "http://localhost:9200/my_index/_update_by_query" -H 'Content-Type: application/json' -d '
{
  "query": {
    "match": {
      "field1": "old_value"
    }
  },
  "script": {
    "source": "ctx._source.field1 = \"new_value\""
  }
}'
```
- **分页查询索引**
```bash
curl -X GET "http://localhost:9200/my_index/_search?size=10&from=0"
```

### 索引ID选择
- **ES自动生成**：自动生成的索引ID具有唯一性和随机性，优点是方便快捷，避免了业务端生成ID可能出现的冲突和重复问题，适合对ID没有特定业务需求的场景。
- **外部业务指定**：外部业务指定的索引ID具有业务含义，便于根据业务逻辑进行数据关联和查询，但需要业务端保证ID的唯一性和正确性，增加了业务端的复杂性，适用于对ID有明确业务要求的场景。

### 分页快照查询与实时查询
- **分页快照查询**：使用scroll API实现分页快照查询。首先，发起一个带有scroll参数的初始查询，获取一个scroll_id：
```bash
curl -X POST "http://localhost:9200/my_index/_search?scroll=1m" -H 'Content-Type: application/json' -d '
{
  "query": {
    "match_all": {}
  },
  "size": 100
}'
```
然后，使用返回的scroll_id进行后续的分页查询：
```bash
curl -X POST "http://localhost:9200/_search/scroll" -H 'Content-Type: application/json' -d '
{
  "scroll": "1m",
  "scroll_id": "your_scroll_id"
}'
```
- **实时查询**：直接使用普通的查询语句进行实时查询，如：
```bash
curl -X GET "http://localhost:9200/my_index/_search?q=field1:value"
```
这种查询会实时返回当前索引中的数据，包括最新写入的数据。
