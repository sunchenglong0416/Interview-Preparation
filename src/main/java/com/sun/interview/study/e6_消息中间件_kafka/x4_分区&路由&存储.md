### 1. Kafka 分区默认路由

**定义**：
Kafka 主题（Topic）可以包含多个分区（Partition）。默认情况下，Kafka 使用以下算法来决定消息路由到哪个分区。

**默认路由算法**：
- **无键消息**：如果消息没有键（Key），Kafka 会使用轮询（Round Robin）算法将消息均匀地分配到各个分区。
- **有键消息**：如果消息有键，Kafka 会使用键的哈希值来决定消息路由到哪个分区。

**公式**：
```java
partition = Math.abs(Utils.murmur2(keyBytes)) % numPartitions
```


**示例**：
假设一个主题有 3 个分区，消息的键为 "key1"。

- **键的哈希值**：`Math.abs(Utils.murmur2("key1".getBytes()))`
- **分区**：`partition = hashValue % 3`

### 2. 指定路由

### 3. 分区内有序

**定义**：
Kafka 确保每个分区内的消息是有序的。消息按照它们被写入分区的顺序进行存储和读取。

**有序性保证**：
- **生产者**：消息按照顺序写入分区。
- **消费者**：消息按照顺序读取分区。

**应用场景**：
- **事件流处理**：确保事件按照时间顺序处理。
- **事务处理**：确保事务操作按照顺序执行。

### 4. 分区内数据存储原理

**数据文件和索引文件**：
- **数据文件（Log File）**：存储实际的消息数据。
- **索引文件（Index File）**：存储消息偏移量（Offset）和物理位置（Position）的映射关系。

**文件结构**：
- **数据文件**：`<topic>-<partition>-<offset>.log`
- **索引文件**：`<topic>-<partition>-<offset>.index`

**存储过程**：
1. **消息写入**：生产者将消息写入数据文件。
2. **索引更新**：Kafka 更新索引文件，记录消息的偏移量和物理位置。

### 5. 索引文件和数据文件的对应关系

**索引文件**：
- **记录**：每个记录包含一个偏移量（Offset）和一个物理位置（Position）。
- **用途**：通过偏移量快速查找消息在数据文件中的位置。

**数据文件**：
- **记录**：每个记录包含消息的偏移量（Offset）、消息长度、消息头和消息体。
- **用途**：存储实际的消息数据。

**示例**：
假设一个主题 `my-topic` 的分区 0 包含以下消息：

- **消息 1**：偏移量 0，物理位置 0
- **消息 2**：偏移量 1，物理位置 100
- **消息 3**：偏移量 2，物理位置 200

**索引文件内容**：
```
0 -> 0
1 -> 100
2 -> 200
```


**数据文件内容**：
```
Offset: 0, Length: 50, Message: "Message 1"
Offset: 1, Length: 60, Message: "Message 2"
Offset: 2, Length: 70, Message: "Message 3"
```


### 6. 查找过程

**查找消息**：
1. **偏移量**：消费者指定要读取消息的偏移量。
2. **索引文件**：Kafka 使用索引文件查找偏移量对应的物理位置。
3. **数据文件**：Kafka 根据物理位置从数据文件中读取消息。

**示例**：
假设消费者要读取偏移量为 1 的消息。

1. **索引文件查找**：
    - 索引文件记录 `1 -> 100`
2. **数据文件读取**：
    - 从数据文件的物理位置 100 读取消息

#### 8.3 分区内有序

**假设**：
- 主题 `my-topic` 的分区 0 包含以下消息：
    - 偏移量 0，消息 "Message 1"
    - 偏移量 1，消息 "Message 2"
    - 偏移量 2，消息 "Message 3"

**消费者代码**：

```java
import org.apache.kafka.clients.consumer.ConsumerConfig;
import org.apache.kafka.clients.consumer.ConsumerRecord;
import org.apache.kafka.clients.consumer.ConsumerRecords;
import org.apache.kafka.clients.consumer.KafkaConsumer;
import org.apache.kafka.common.serialization.StringDeserializer;

import java.time.Duration;
import java.util.Collections;
import java.util.Properties;

public class OrderedConsumerExample {
    public static void main(String[] args) {
        Properties props = new Properties();
        props.put(ConsumerConfig.BOOTSTRAP_SERVERS_CONFIG, "localhost:9092");
        props.put(ConsumerConfig.GROUP_ID_CONFIG, "my-group");
        props.put(ConsumerConfig.KEY_DESERIALIZER_CLASS_CONFIG, StringDeserializer.class.getName());
        props.put(ConsumerConfig.VALUE_DESERIALIZER_CLASS_CONFIG, StringDeserializer.class.getName());
        props.put(ConsumerConfig.AUTO_OFFSET_RESET_CONFIG, "earliest");

        KafkaConsumer<String, String> consumer = new KafkaConsumer<>(props);
        consumer.subscribe(Collections.singletonList("my-topic"));

        while (true) {
            ConsumerRecords<String, String> records = consumer.poll(Duration.ofMillis(100));
            for (ConsumerRecord<String, String> record : records) {
                System.out.printf("offset = %d, key = %s, value = %s%n", record.offset(), record.key(), record.value());
            }
        }
    }
}
```


**解释**：
- 消费者订阅主题 `my-topic`。
- 消费者按消息的偏移量顺序读取分区中的消息，确保分区内有序。
