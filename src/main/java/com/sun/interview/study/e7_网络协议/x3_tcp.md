
TCP（Transmission Control Protocol）即传输控制协议，是一种面向连接的、可靠的、基于字节流的传输层通信协议。以下是对TCP协议的介绍及各部分组成：

TCP协议概述
TCP协议位于传输层，它在IP协议提供的基本数据报服务的基础上，为应用程序提供了一种可靠的、有序的、无差错的数据传输服务。TCP协议通过一系列的机制，如三次握手建立连接、滑动窗口进行流量控制、确认和重传机制保证数据的可靠传输等，使得网络中的数据能够准确无误地从发送端传输到接收端。

TCP协议头部格式及各部分组成
TCP协议的数据单元称为报文段，报文段由首部和数据两部分组成。首部的前20个字节是固定的，后面有4n字节是根据需要而增加的选项（n是整数）。以下是TCP首部各部分的介绍：
- 1. **源端口号（Source Port）**：16位字段，标识发送端应用程序使用的端口号。
- 2. **目的端口号（Destination Port）**：16位字段，标识接收端应用程序使用的端口号。通过源端口号和目的端口号，TCP可以将数据准确地交付给相应的应用程序进程。
- 3. **序号（Sequence Number）**：32位字段，用来标识从TCP发送端向TCP接收端发送的数据字节流中的每个字节的编号。在连接建立时，发送方和接收方会各自随机选择一个初始序号，后续的序号则根据发送的数据字节数依次递增。
- 4. **确认号（Acknowledgment Number）**：32位字段，是期望收到对方下一个报文段的第一个数据字节的序号。例如，B收到了A发送过来的报文段，其序号字段值为1000，数据长度为100字节，那么B期望收到A的下一个报文段的第一个数据字节的序号为1100，此时B发送给A的确认号就为1100。
- 5. **数据偏移（Data Offset）**：4位字段，也称为首部长度字段，它指出TCP报文段的数据部分距离TCP报文段的起始处有多远。该字段以4字节为单位，因此取值范围是0 - 15，表示首部长度为0 - 60字节（因为TCP首部最长为60字节，包含20字节的固定部分和最多40字节的选项部分）。
- 6. **保留（Reserved）**：6位字段，保留为今后使用，目前必须置为0。
- 7. **控制位（Control Bits）**：6位字段，包含了6个标志位，用于控制TCP的连接和数据传输过程。
-     - **URG（Urgent）**：紧急指针标志位。当URG = 1时，表明紧急指针字段有效，通知接收方此报文段中有紧急数据，应尽快处理。
-     - **ACK（Acknowledgment）**：确认标志位。当ACK = 1时，确认号字段才有效。在连接建立后，所有传送的报文段都必须把ACK置为1。
-     - **PSH（Push）**：推送标志位。当PSH = 1时，表明发送方希望接收方尽快将此报文段中的数据交付给应用程序，而不要等到整个缓存都填满后再交付。
-     - **RST（Reset）**：复位标志位。当RST = 1时，表明出现了严重错误，必须释放连接，然后再重新建立连接。
    - **SYN（Synchronize）**：同步标志位。在连接建立时，用于同步序号。当SYN = 1，ACK = 0时，表示这是一个连接请求报文段；当SYN = 1，ACK = 1时，表示这是一个连接响应报文段。
    - **FIN（Finish）**：结束标志位。当FIN = 1时，表明发送方的数据已发送完毕，要求释放连接。
- 8. **窗口大小（Window）**：16位字段，用于告知对方自己的接收窗口大小，即接收方当前可以接收的数据量。接收方通过调整这个窗口大小来进行流量控制，防止发送方发送数据过快导致接收方缓冲区溢出。
- 9. **检验和（Checksum）**：16位字段，用于检测TCP报文段在传输过程中是否发生了错误。计算检验和时，需要包括TCP首部、数据部分以及一个伪首部，伪首部包含了IP首部中的一些字段，如源IP地址、目的IP地址等，这样可以确保TCP报文段在传输过程中的完整性和准确性。
- 10. **紧急指针（Urgent Pointer）**：16位字段，当URG标志位为1时，紧急指针字段才有效。它指出在本报文段中紧急数据的最后一个字节的序号，以便接收方能够快速定位和处理紧急数据。
- 11. **选项（Options）**：长度可变，最多可达40字节。常见的选项有最大报文段长度（MSS）、窗口扩大因子、时间戳等。MSS选项用于在连接建立时，双方协商最大的报文段长度，以避免数据在网络中传输时发生分片；窗口扩大因子选项用于扩大窗口大小，以适应高速网络环境；时间戳选项用于记录报文段的发送和接收时间，可用于计算往返时间（RTT）等。
- 12. **填充（Padding）**：由于选项字段的长度不一定是4字节的整数倍，当选项字段的长度不是4字节的整数倍时，需要使用填充字段将TCP首部的长度填充为4字节的整数倍。

通过以上各部分的协同工作，TCP协议能够在不可靠的网络环境中实现可靠的数据传输，为各种网络应用提供了坚实的基础。


三次握手-建立连接
- **第一次握手**：客户端向服务器发送一个SYN（Synchronize Sequence Numbers，同步序列编号）包，其中包含客户端的初始序列号（Sequence Number，seq），假设为x，此包表明客户端请求与服务器建立连接。
- **第二次握手**：服务器接收到客户端的SYN包后，会向客户端发送一个SYN + ACK（Acknowledgment，确认）包。该包中，服务器将自己的初始序列号设为y，并将客户端的序列号x加1作为确认号（Acknowledgment Number，ack），即ack = x + 1，表示已收到客户端的SYN包，同时也请求客户端确认服务器的SYN包。
- **第三次握手**：客户端收到服务器的SYN + ACK包后，会向服务器发送一个ACK包。该包的确认号为服务器的序列号y加1，即ack = y + 1，序列号为x + 1，表示客户端已收到服务器的SYN + ACK包，连接建立成功。此时，客户端和服务器都进入ESTABLISHED（已建立连接）状态，可以开始传输数据。

ACK确认机制是为了防止TCP连接攻击 耗尽服务器TCP连接数

四次挥手-安全断开
- **第一次挥手**：客户端发送一个FIN（Finish，结束）包，其中包含客户端的序列号seq = u，表示客户端希望关闭连接，不再发送数据，但仍可以接收数据。
- **第二次挥手**：服务器收到客户端的FIN包后，会发送一个ACK包作为应答，确认号ack = u + 1，序列号为服务器当前的序列号v，表示已收到客户端的FIN包。此时，客户端进入FIN_WAIT_1（终止等待1）状态，服务器进入CLOSE_WAIT（关闭等待）状态。
- **第三次挥手**：服务器处理完剩余数据后，向客户端发送一个FIN包，其中序列号为w，确认号仍为u + 1，表示服务器也准备关闭连接。此时，服务器进入LAST_ACK（最后确认）状态。
- **第四次挥手**：客户端收到服务器的FIN包后，发送一个ACK包进行确认，确认号ack = w + 1，序列号为u + 1。客户端进入TIME_WAIT（时间等待）状态，服务器收到ACK包后，进入CLOSED（关闭）状态。客户端在TIME_WAIT状态停留一段时间（通常为2倍的MSL，即Maximum Segment Lifetime，最长报文段寿命）后，也会进入CLOSED状态，连接彻底关闭。

通过三次握手和四次挥手，TCP能够确保连接的可靠建立和关闭，保证数据传输的准确性和完整性。


# TCP攻击

TCP攻击是一类针对传输控制协议（TCP）的网络攻击方式，常见的有以下几种：

### SYN Flood攻击
- **原理**：攻击者发送大量带有SYN标志的TCP连接请求包，但不完成三次握手的后续步骤。服务器收到这些请求后，会为每个连接分配资源并等待客户端的确认，由于攻击者不发送最后的ACK包，服务器的连接队列会被大量半开连接填满，导致正常的连接请求无法被处理。
- **防范措施**：可以采用SYN cookies技术，服务器在收到SYN包时，不立即分配资源，而是根据一定算法生成一个特殊的序列号（cookie）作为SYN - ACK包的初始序列号发送给客户端。当客户端返回ACK包时，服务器验证这个序列号是否正确，从而判断是正常连接还是攻击包。还可以设置合理的连接超时时间，及时清理半开连接。

### TCP RST攻击
- **原理**：攻击者向正在进行通信的TCP连接发送带有RST标志的数据包，强制关闭连接。接收方收到RST包后，会立即中断连接，导致正在进行的数据传输中断。
- **防范措施**：对RST包进行合法性检查，例如检查源IP地址、端口号、序列号等是否与当前连接匹配。同时，采用加密技术对TCP连接进行保护，使攻击者难以伪造合法的RST包。

### TCP会话劫持攻击
- **原理**：攻击者通过监听网络流量获取TCP连接的相关信息，如序列号、确认号等，然后冒充其中一方与另一方进行通信，接管整个会话。攻击者可以在会话中插入、篡改或窃取数据。
- **防范措施**：使用加密协议（如SSL/TLS）对数据进行加密，使攻击者难以获取和篡改传输中的数据。同时，采用端口绑定技术，将TCP连接与特定的IP地址和端口绑定，防止攻击者冒充合法的通信方。

### Land攻击
- **原理**：攻击者构造一个源IP地址和目标IP地址都为受害者主机IP地址，且源端口和目标端口也相同的TCP SYN包，发送给受害者主机。受害者主机收到这样的数据包后，会向自己发送SYN - ACK包，并等待自己的ACK包，形成一个死循环，导致系统资源耗尽，最终可能导致系统崩溃。
- **防范措施**：配置防火墙，对源IP地址和目标IP地址相同的数据包进行过滤。同时，及时更新操作系统和网络设备的补丁，修复可能存在的相关漏洞。
